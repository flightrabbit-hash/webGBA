# webGBA 설계

webGBA 는 Tauri 2 웹뷰로 도는 GBA 실행기입니다. `.gba`(`.zip`)는 앱 `bin\core` 의 mGBA wasm 코어로,
`.wasm` 은 내장 호스트(Web_* 규약) 또는 그 웹 빌드의 원래 페이지·글루로 앱 안에서 실행합니다.

- 구조 원본: 아비터(같은 저작권자의 별도 Tauri 2 프로젝트, arbiter 1.2.12). 폴더 배치·빌드 스크립트·설정 방식·코드 관례를 따릅니다.
- 매크로 기능(입력 녹화·실행 키·서버·트레이·전역 단축키)은 가져오지 않았습니다.

### 관리자 권한을 쓰지 않는다 (사용자 2026-10-26)

- 아비터는 `requireAdministrator` 매니페스트로 뜬다(매크로가 관리자 창에 입력을 보내야 해서). webGBA 는 **`asInvoker`(일반 권한)**.
  - `src-tauri/windows-app-manifest.xml` 의 `requestedExecutionLevel level="asInvoker"`. Common-Controls 의존성과 "XML 선언 금지·ASCII 만" 규칙은 그대로.
- 관리자 권한 때문에 생긴 우회 코드는 가져오지 않았다.
  - UIPI 메시지 필터 개방(`ChangeWindowMessageFilter(Ex)` — `WM_DROPFILES`·`WM_COPYDATA`·`0x0049`)
  - `osdrop.rs`(wry 끌어 놓기 처리기를 끄고 WebView2 기본 외부 Drop + `postMessageWithAdditionalObjects` 로 경로를 받는 우회. 아비터 Cargo.toml 주석대로 "관리자 권한 + WebView2 하위 창에서 wry 처리기가 동작하지 않아" 생긴 것)
  - `run-app.cjs` 의 `Start-Process -Verb RunAs`, `scripts.cjs` 의 "관리자 권한 터미널 전용" 구분, build-fresh 의 관리자 안내
- 끌어 놓기는 **wry 기본 처리기**(Tauri `WindowEvent::DragDrop`)로 받고, Rust(`bridge/events.rs`)가 아비터와 같은 화면 이벤트(`webgba:os-drag` `{phase, at}`, `webgba:os-drop` `{paths, at}`)로 바꿔 넘긴다. 좌표는 물리 픽셀 → CSS 픽셀.
- 확인(2026-10-26): exe 매니페스트 `asInvoker`, 실행 중 프로세스 무결성 0x2000(Medium), 일반 권한 프로세스의 OLE `DoDragDrop`(탐색기와 같은 길)으로 `.gba` 를 끌어 놓아 열림(시험 D1).

## 3. 빌드

| 명령 | 내용 |
| --- | --- |
| `npm run core` | `core/build.sh` 를 도커 `emscripten/emsdk:4.0.10` 에서 `--rm`·15분 제한으로 실행 → `src-bundle/bin/core/mgba_core.wasm`(+라이선스) |
| `npm run dist` | `src-bundle/build-dist.cjs`: `src-bundle/src`·`bin`·`ini` → `dist/` |
| `npm run dev` | 디버그 빌드 후 실행 |
| `npm run build` | `tauri build`(bundle 비활성 → `src-tauri/target/release/webgba.exe`, 옆에 `LICENSE`·`THIRD_PARTY_NOTICES`·`bin\core\` 리소스) |
| `npm start` | 릴리스 실행 파일 실행 |

- 아비터의 `minify.cjs`(공백·주석 압축)는 가져오지 않았다. 배포 파일에 주석을 두지 않는 규칙만 지키고 그대로 복사한다(합쳐 120KB 남짓).
- `mgba_core.wasm` 은 저장소에 결과물로 둔다(도커 없이도 앱 빌드가 되게).

## 4. 실행 구조

```text
 webgba.exe (Rust)                                  웹뷰 (본 창 하나)
 ┌───────────────────────────────┐   invoke     ┌────────────────────────────────────────────┐
 │ bridge::commands              │ ◀──────────  │ js/bridge.js                                │
 │  core_read (bin/core 코어)      │ ──────────▶  │ js/pages/index.js (메뉴·탐색기·열기 흐름)    │
 │  rom_read (.gba/.zip)·file_list │   event      │ js/app/player.js (루프·키·소리·세이브·상태) │
 │  save_* (옆 .sav)·store_* (상태)│              │ js/core/web-host.js (내장 호스트, Web_*)   │
 │  web_inspect (빌드 출처 등록)   │              │ <iframe> 웹 빌드 (출처 game.<키>.localhost) │
 │ 스킴 ui   : dist/ 내장 자산      │              └────────────────────────────────────────────┘
 │ 스킴 game : 웹 빌드 폴더(비동기)  │
 │ DragDrop → webgba:os-drag/drop │
 └───────────────────────────────┘
```

- 큰 바이트(롬 32MB, 코어, 세이브·상태)는 `tauri::ipc::Response`(원시 ArrayBuffer)로 넘기고, 쓰기는 원시 요청 본문(`InvokeBody::Raw`) + 헤더(`x-game`·`x-store`·`x-slot`·`x-path`, 퍼센트 인코딩)로 받는다.
- 세이브는 연 파일 경로로 오간다: 열 때 `save_path`·`save_read` → 게임이 쓰면 `save_write`(헤더 `x-game`), 메뉴 가져오기는 `save_import`(둘 다 `store::write` 로 그 파일을 직접 덮어씀). 자리는 늘 `<연 파일 폴더>\<이름>.sav`(`store::beside_of`).
- 상태 슬롯 1~9 만 "저장 이름"으로 오간다: `gba/<롬 이름>` → `bin/state`, `web/<빌드 이름>-<키>` → `bin/web/<…>/`. 이름의 경로 문자는 `_` 로 바뀌어 폴더를 벗어나지 못한다(`store::clean_name`).

## 5. 내장 호스트와 Web_* 규약 (사용자 2026-10-26: .js 없이 .wasm 하나로)

### 규약
우리 포트 `firered.wasm` 이 이미 쓰는 내보내기 이름을 그대로 규약으로 삼고, mGBA 코어도 같은 이름으로 내보낸다. webGBA 의 내장 호스트(`js/core/web-host.js`) 하나가 둘 다 돌린다.

| 내보내기 | 필수 | 뜻 | 포트 | mGBA 코어 |
| --- | --- | --- | --- | --- |
| `memory` | ● | 선형 메모리 | ● | ● |
| `Web_Init()` | ● | 롬·세이브를 놓은 뒤 시작, 0 이면 실패 | ● | ● |
| `Web_RunFrame(keys)` | ● | 1프레임. KEYINPUT 비트(A0 B1 SELECT2 START3 →4 ←5 ↑6 ↓7 R8 L9, 눌림=1). 0 이면 멈춤 | ● | ● |
| `Web_GetFramebuffer()` | ● | 240x160 RGBA(mGBA 코어 GB·GBC 는 160x144) | ● | ● |
| `Web_SetAudioRate`·`Web_GetAudioBuffer`·`Web_GetAudioCount` | | float 스테레오 교차, 이번 프레임 표본 수 | ● | ● |
| `Web_GetFlash`·`Web_FlashClear`·`Web_TakeFlashDirty` | | 세이브 버퍼(포트 512KB·mGBA 128KB)·지우기·게임이 썼는지 | ● | ● |
| `Web_GetSaveSize` | | 세이브 크기(없으면 128KB). 지운 직후의 값이 버퍼 크기 | ●(PC 박스 30 판부터 512KB 고정) | ● |
| `Web_SetSaveSize` | | 불러온 세이브 크기를 코어에 알림 | | ● |
| `Web_GetHaltReason` | | 멈춘 까닭 문자열 | ● | ● |
| `Web_RomBuffer(size)` | | 롬 자리(없으면 0x08000000 고정) | | ● |
| `Web_Reset` | | 재시작(없으면 호스트가 인스턴스를 새로 만듦) | | ● |
| `Web_StateSize`·`Web_StateSave`·`Web_StateLoad`·`Web_Alloc`·`Web_Free` | | 상태 저장 | | ● |
| `Web_GetTitle`·`Web_GetCode`·`Web_GetFrameCount`·`Web_SetTimeZone` | | 정보·RTC 시차 | 일부 | ● |
| `Web_GetScreenWidth`·`Web_GetScreenHeight`·`Web_GetSystem` | | 지금 게임의 화면 크기(설명서 `screen` 이 없을 때만 호스트가 씀)·기종(0 GBA·1 GB·2 GBC 모드). 20절 | | ● |
| `Web_Pointer(x, y, buttons, wheel)` | | 마우스: 게임 픽셀 좌표(화면 밖 -1), 눌린 버튼(`MouseEvent.buttons` 1 왼쪽·2 오른쪽·4 가운데), 지난 호출 뒤 휠 칸 수(+ 아래). 14절 | ●(2026-10-30 AC14-C, 포토체스 화면만 씀) | |
| `Web_PointerWanted()` | | 1 이면 게임이 지금 마우스를 씀(호스트가 캔버스 우클릭 메뉴를 막음) | ● | |
| `Web_NetWanted`·`Web_NetEvent`·`Web_NetOut`·`Web_NetOutLen`·`Web_NetOutClear`·`Web_NetInBuffer`·`Web_NetIn` | | 멀티플레이(규격 7장, 일곱 개가 모두 있어야 씀). 호스트 한 프레임: 받은 것 넣기 → `Web_RunFrame` → 보낼 것 꺼내기 → `Web_NetWanted` 읽기. 15절 | (MP3부터) | |
| `Web_NetHost(protocol, flags)`·`Web_NetCompat()` | | 호스트가 규약 1 을 앎(flags 1 = 순서 방송) · 게임 호환 키(NUL 끝 ASCII 64자) | | |
| `Web_NetBoard()` | | 플레이어 상태 표 400바이트 버퍼 위치(규격 7.9.2, 세션이 열린 뒤 한 번, 설명서 `multiplayer.board` 가 있을 때만). 17절 | (MP4a 포토체스) | |

- 규약이 포트와 다른 곳과 까닭
  - **롬 자리**: 포트는 GBA 주소 공간을 선형 메모리에 그대로 두어 롬이 0x08000000 고정이다. mGBA 는 롬을 힙에 받으므로 `Web_RomBuffer(size)` 로 자리를 받는다. 없으면 0x08000000 → 포트는 그대로 돈다.
  - **세이브 크기**: 포트는 2026-10-26 PC 박스 30개부터 512KB 고정(`Web_GetSaveSize` 만 내보냄. 앞 128KB 는 옛 형식 그대로라 옛 128KB 세이브를 앞에 넣으면 게임이 읽어 옮김). mGBA 는 게임마다 SRAM 32KB·플래시 64/128KB·EEPROM 이 달라 `Web_GetSaveSize/SetSaveSize` 를 더했다. 없으면 128KB. 호스트가 넣을 수 있는 크기(`saveCapacity`)는 128KB 와 `Web_GetSaveSize` 중 큰 값이고, 저장은 코어가 내놓는 크기 그대로(128KB 로 자르지 않음). 옛 128KB 세이브는 처음 저장할 때 그 파일이 그대로 512KB 로 덮어써진다(백업 없음). `/save` 호환 경로·메뉴 가져오기는 Rust 쪽에서는 크기를 보지 않고(16MB 까지) 파일 그대로 다룬다.
  - **재시작·상태 저장**: 포트에는 없어서 선택 항목. 포트의 재시작은 호스트가 같은 모듈로 인스턴스를 새로 만들고 지금 세이브를 다시 넣는다. 포트의 상태 저장은 지원하지 않는다(선형 메모리가 190MB 라 통째 저장은 무거움 — 결정필요사항 3).
- 호스트가 롬을 코어에 넘기는 곳은 `WebHost.placeRom` 한 곳이다(나중에 "GBA → wasm 변환·묶기"를 넣을 때 여기만 바꾸면 됨). 롬 바이트를 읽는 곳도 `index.js` 의 `loadRomBytes` 한 곳.

## 6. `.wasm` 열기 — 범용 (사용자 2026-10-26)

우리 포트의 `app.js` 함수 이름·세이브 방식에 묶지 않는다. 열기 순서:

1. **가져오기 검사**: wasm 을 읽어 `WebAssembly.compile` → `inspectModule`. 가져오기가 모두 위 "아는 함수"이고 필수 내보내기(`memory`·`Web_Init`·`Web_RunFrame`·`Web_GetFramebuffer`)가 있으면 → **내장 호스트**로 바로 실행(.js 불필요). 우리 포트의 모든 판과 mGBA 코어가 여기.
   - 롬을 묶은 `.wgba`(사용자 정의 구획 `webgba.rom`, 8절 "롬을 묶은 `.wgba`")면 그 롬을 쓰고 아래 찾기·고르기를 하지 않는다.
   - 롬(2026-10-27 공개 전 정리, 롬 이름을 코드에 박지 않음): 기억해 둔 롬(`personalization.cfg` 의 `webBuilds[키]`, 메뉴 "롬 지정…"·처음 열 때 고른 것) → 짐작(`web::guess_rom`, 각 단계는 같은 폴더 → 위 폴더 순) ① 설정 "웹 빌드에 쓸 롬 파일 이름"(`webRom`, 기본 비움, 절대 경로도 됨) ② `<빌드 이름>.gba` ③ 같은 폴더의 `.gba` 가 하나뿐이면 그것(같은 폴더에 `.gba` 가 없을 때만 위 폴더에서 같은 규칙, 여럿이면 짐작하지 않음) → 그래도 없으면 열기 대화상자, 고른 롬을 `webBuilds[키]` 에 기억. 사용자 배포본(`webGBA\firered.wgba` 옆에 롬이 하나)은 ③으로 그대로 열린다.
   - 세이브: 연 파일 옆 `<빌드 이름>.sav`(8절). 롬 옆 세이브(`Pokemon Fire Red (E).sav` 등)는 보지 않는다.
2. **페이지가 있는 웹 빌드**: 같은 폴더에 `<이름>.html` 또는 `index.html` 이 있으면 그 페이지를 앱 안 `<iframe>` 에서 그대로 연다. 내장 호스트가 되는 빌드라도 메뉴 "원래 페이지로 열기"로 이쪽을 고를 수 있다.
3. **페이지 없이 글루가 있는 빌드**: 같은 이름 `.js`/`.mjs` 가 있으면 `/__webgba__/wasm-host.html?js=<이름>.js` 로 캔버스(`#canvas`)와 표준 `Module`(`canvas`·`locateFile`·`print`·`printErr`·`setStatus`·`arguments`·`onAbort`)을 붙여 실행. MODULARIZE(새로 생긴 전역 팩토리 함수, `EXPORT_NAME` 무관)·보통 글루·`.mjs`(ES 모듈 `default`) 모두.
4. 그 밖: "이 wasm 은 함께 빌드된 .js 가 필요합니다 (모르는 바깥 함수: …)".

- 내장 호스트를 페이지보다 먼저 쓰는 까닭: .gba 와 같은 화면·키 설정·배속·일시정지·세이브 파일(연 파일 옆 `<이름>.sav`, VBA 와 같은 형식)을 그대로 쓰고, 빌드 폴더의 `app.js` 에 기대지 않는다. 원래 페이지가 필요하면 메뉴로 바로 바꿀 수 있다.

### 빌드마다 출처를 따로 준다(저장 공간 분리)
- 스킴 `game` 하나를 등록하고 빌드마다 주소를 `http://game.<키>.localhost/` 로 만든다. `<키>` = .wasm 실제 경로(소문자)의 FNV-1a 64비트 앞 12자리.

  - 출처가 빌드마다 달라 **localStorage·IndexedDB·IDBFS·쿠키가 섞이지 않는다**(시험 W4). 키는 경로에서 나오므로 앱을 다시 열어도 같은 출처라 **남는다**(시험: IDBFS 횟수 1 → 2).

  - 웹뷰 데이터 폴더는 `bin/webview/`(`data_directory`) → 웹 빌드 저장 공간도 webGBA 앱 데이터 안.

  - 출처 하나(`game.localhost`)에 경로만 나누기: localStorage·IndexedDB 는 출처 단위라 빌드끼리 섞인다.
  - 빌드마다 창을 따로 띄우고 `data_directory` 를 나누기: 창이 여러 개가 되고 WebView2 브라우저 프로세스가 빌드마다 는다.

### 세이브 — 연 파일 옆 `<이름>.sav` 하나를 직접 덮어씀 (사용자 2026-10-27)
사용자 말: "파일 옆에있는 sav파일을 제대로 못불러오는거같아. 다른 경로에 세이브파일 저장은 제외하고 파일 옆에 저장하도록",
이어서 "외부 세이브파일 불러오기는 유지하되 자동저장 기능은 같은 경로의 sav파일을 직접수정하는걸로 변경 … 백업과 비교 등의 기능은 필요없어".

- **자리**: 연 파일(.gba·.zip·.wgba·.wasm) 바로 옆 `<연 파일 이름>.sav` 하나뿐(`store::beside_of`). 앱 안쪽 저장소·"세이브 파일 폴더" 설정·롬 옆 세이브 규칙(`.wgba` 가 쓰는 롬 옆 `Pokemon Fire Red (E).sav`)은 없앴다. `firered.wgba` 와 `firered.wasm` 이 한 폴더에 있으면 둘 다 `firered.sav` 를 쓴다.
- **열 때**: 옆 `.sav` 가 있으면 그대로 읽는다(수정 시각 비교·가져오기 판단 없음). 없으면 빈 세이브로 시작하고 상태 줄에 "저장하면 <이름>.sav 에 씁니다". 파일이 있는데 읽지 못하면(잠김·폴더 등) 빈 세이브로 시작하지 않고 열기를 실패시킨다 — 빈 세이브가 진짜 세이브를 덮어쓰지 않게.
- **쓸 때**: 게임이 세이브를 쓰면(플래시·SRAM 쓰기가 끝나 `Web_TakeFlashDirty`) 마지막 쓰기 1초 뒤 한 번(`player.js` `SAVE_DELAY_MS`). 창 닫기(X·Alt+F4·끝내기)·Ctrl+W·다른 파일 열기·일시정지·다시 시작 때는 기다리지 않고 바로. 닫을 때는 밀린 것이 없어도 코어 세이브가 열 때와 다르면 쓴다. 크기는 코어 세이브 그대로(포트 512KB). 내용이 디스크와 같으면 쓰지 않는다.
- **직접 덮어쓰기**: 그 `<이름>.sav` 파일 자체를 열어(`OpenOptions` write·create, 자르지 않고) 처음부터 쓰고, 새 내용이 더 짧으면 `set_len` 으로 뒤쪽을 자른 뒤 `sync_all`(`files::write_in_place`). 임시 파일·이름 바꾸기·백업이 없어 그 폴더에 다른 파일이 생기지 않는다. 열기가 OneDrive·백신 때문에 잠깐 막히면 40ms 간격으로 8번 다시 해 본다.
- **못 쓸 때**(읽기 전용·폴더 쓰기 금지·디스크 가득 등): 다른 곳에 따로 남기지 않는다. 상태 줄에 "세이브를 쓰지 못했습니다(다음 저장 때 다시 씁니다)"와 이유, 기록(log)에 경로. 메모리의 세이브는 그대로 두고(`player.js` `savePending` 유지) 게임이 다음에 저장할 때·닫을 때 다시 쓴다. 창을 닫는 그 순간의 쓰기까지 실패하면 그 진행은 남지 않는다.
- **가져오기·내보내기**: 메뉴 "세이브 가져오기…"는 고른 파일(크기 확인 → 확인 창)의 내용으로 옆 `.sav` 를 같은 방식으로 직접 덮어쓰고 게임을 다시 연다(지금 옆 파일 내용은 남지 않음, 백업 없음). "세이브 내보내기…"는 지금 세이브를 고른 자리에 그대로 쓴다.
- **없앤 것(사용자 2026-10-27)**: `.sav.bak`(처음 덮어쓰기·가져오기 때), 옛 판 앱 안쪽 세이브(`bin\save\<이름>.sav`·`bin\web\<이름>-<키>\save.sav`) 옮기기와 저장 횟수·수정 시각 비교, `.sav.bak-옛webGBA`, `.migrated` 이름 바꾸기, 못 쓸 때의 `bin\rescue\`, 열 때 부르던 `save_open`. 옛 판이 남긴 파일(안쪽 `save.sav`·`save.sav.migrated`, 옆 `.sav.bak`)은 읽지도 지우지도 않는다.
- **`.wasm` → `.wgba`**: 이름이 같으면 옆 `.sav` 도 같아 세이브는 그대로 이어진다. 앱 안쪽 폴더(상태 슬롯)는 처음 열 때 `.wgba` 키 쪽으로 옮기고 기억한 롬도 넘긴다(`web::adopt_wasm_states`).
- 이전 판의 문제(재현 2026-10-27): 옛 판은 앱 안쪽이 본체이고 옆 `.sav` 는 "수정 시각이 더 새것"일 때만 가져왔다. Windows 탐색기 복사는 원본의 수정 시각을 그대로 두므로, 몇 시간 전에 만든 시험 세이브를 `firered.sav` 로 복사해 넣으면 최근에 쓴 안쪽 세이브보다 옛것으로 보여 무시되고, 닫을 때 "종료 세이브"가 안쪽 것으로 덮어써 넣은 파일이 `firered.sav.bak` 으로 밀려났다. 지금은 옆 파일 하나만 보므로 이런 일이 없다.

### 롬을 묶은 `.wgba` (사용자 2026-10-27)
사용자 말: "wgba 파일이 이 PC에서는 정상적으로 열리는데 다른PC에서는 드래그&드롭 시 파일선택다이얼로그가 한번 뜨고 선택 시 메모리 오류가 나와",
이어서 "gba 파일이 있어야지만 열리는거야? 없이 열리게 하는걸 원해" → ".wgba 안에 롬 넣기"로 정함.
원인: 다른 PC 에는 옆에 맞는 롬이 없어 롬 고르기 창이 뜨고, 원본 롬 등 다른 롬을 고르면 포트가 핵 롬에만 있는 자리를 읽다가 메모리 범위 밖 오류로 멈춘다.

- **형식**: wasm 끝에 사용자 정의 구획(custom section, id 0) 하나, 이름 `webgba.rom`. wasm 엔진은 사용자 정의 구획을 무시하므로 묶은 파일도 그대로 올바른 wasm 이고(`WebAssembly.validate`), 구획이 없던 wasm 을 묶으면 앞부분은 원래 wasm 과 바이트까지 같다. 구획 내용(little endian):

  | 위치 | 크기 | 내용 |
  | --- | --- | --- |
  | 0 | 4 | `WGRM` |
  | 4 | 2 | 머리 길이(36). 읽는 쪽은 이 값만큼 건너뛰므로 뒤에 칸을 더해도 옛 판이 읽는다 |
  | 6 | 1 | 형식 판 1 |
  | 7 | 1 | 방식: 0 그대로, 1 zlib(RFC 1950 — 웹뷰 `DecompressionStream("deflate")`, Rust `flate2`) |
  | 8 | 4 | 롬 크기(32MB 이하) |
  | 12 | 4 | 묶은 크기 |
  | 16 | 20 | 롬 SHA-1 |
  | 36 | … | 묶은 롬 |

- **묶기**: `node tools/pack-wgba.mjs <빌드.wasm|.wgba> <롬.gba> <출력.wgba> [--store] [--level 0-9]`(node 만, 의존성 없음). 이미 구획이 있으면 바꿔 넣는다. 옆 임시 파일에 쓰고 다시 읽어 wasm 검사·압축 풀기·SHA-1 을 확인한 뒤 이름을 바꾼다(실패하면 원래 파일 그대로). `--info <파일>` 은 묶인 롬 정보(없으면 끝 상태 3), `--strip <파일> <출력>` 은 구획을 뺀 wasm. 포트 배포본은 롬이 43% 로 줄어 wasm 20.1MB → .wgba 27.3MB, 묶기 약 1초.
- **열기**(`index.js` `openWasm`): 파일을 읽어 `WebAssembly.compile` 한 뒤 `web-host.js` `readEmbeddedRom(module)` 이 `WebAssembly.Module.customSections(module, "webgba.rom")` 의 마지막 것을 꺼내 머리 확인 → 풀기 → 크기 → SHA-1(`crypto.subtle`) 을 확인한다. 구획이 있으면 그 롬을 코어에 넘기고(`bootHost` → `placeRom`), 롬 찾기·고르기 창·`webSetRom`·기억(`webBuilds`)을 하지 않는다. 상태 줄 "<이름> · 내장 롬 · 세이브 …", 게임 메뉴 "롬 지정…" 은 꺼진다. 구획이 없으면 6절 1 의 규칙 그대로.
  - 망가진 구획은 열지 않고 "내장 롬이 손상되었습니다(SHA-1 이 다름 / 압축을 풀지 못함 / 풀린 크기가 다름 / 머리를 읽지 못함). .wgba 를 다시 묶어 주세요", 모르는 형식 판·방식은 "이 webGBA 가 모르는 내장 롬 형식입니다(판 · 방식). webGBA 를 새 판으로 바꿔 주세요"(세 언어, `host.embed*`).
  - 원래 페이지·글루로 열 때도 화면이 먼저 같은 확인을 하고, 페이지의 `GET /rom` 은 Rust 가 준다: `web::inspect` 가 파일의 구획 머리만 따라가 자리를 찾아 두고(`embed::find`, 파일 전체를 읽지 않음), 요청 때 그 자리를 읽어 푼다(`embed::read`, 크기 확인). 묶인 빌드는 롬 짐작(`guess_rom`)을 하지 않는다(`Build.romEmbedded`).
  - 세이브는 그대로 연 파일 옆 `<이름>.sav`.
  - 시간(포트 배포본, 같은 앱에서 세 번의 가운데): 구획 없는 .wgba + 옆 롬 418ms, 묶은 .wgba 414ms. 롬을 따로 읽어 오는 16MB 대신 7.3MB 를 더 읽고 풀기·SHA-1 이 약 0.1~0.15초 든다.
- **배포**: 롬은 저장소·dist·exe·릴리스 어디에도 넣지 않는다. 묶기는 롬을 가진 사람이 자기 PC 에서 하고, 묶은 `.wgba` 는 롬이 들어 있으므로 나눠 주지 않는다(`.gitignore` 의 `*.wgba`·`*.gba`). 나눠 줄 때는 아래 `.wgbp`.
- **압축은 pako**(2026-10-28): `pack-wgba.mjs` 의 zlib 은 저장소 안 pako 2.1.0(`src-bundle/src/js/vendor/pako.js`, level 9)으로 한다. 앱이 `.wgbp` 로 `.wgba` 를 만들 때와 같은 코드(`js/core/wgbp.js` 의 `romPayloadFrom`)라, 같은 wasm·같은 롬이면 어느 PC 에서 묶어도 파일 전체가 바이트까지 같다. 전에는 node 내장 zlib(Chromium 판, 표준 zlib 과 결과가 다르고 PC 마다 같다는 보장이 없음)이었다. 포트 롬은 7,258,577 → 7,217,418바이트. 읽는 쪽·형식 판은 그대로(옛 .wgba 도 그대로 읽힘).

### 롬 없는 공유용 패치 `.wgbp` (사용자 2026-10-28)
사용자 말: "firered 영문판 정식 개인롬을 가진 사람 기준으로 개조버전을 즐길 수 있도록 패치파일을 만들거야. 만든 결과물은 우리의 wgba와 같은 파일로 나올거고", "1.0과 1.1 둘 다 대응".

- **무엇**: 롬이 들어 있지 않아 나눠 줄 수 있는 파일. 열면 사용자가 자기 롬을 한 번 고르고, 앱이 같은 폴더에 `<.wgbp 이름>.wgba`(롬을 묶은 것)를 만들어 바로 연다. 다음부터는 그 `.wgba` 를 연다(롬 없는 PC 로 옮겨도 열림). 세이브는 그 `.wgba` 옆 `<이름>.sav`.
- **만들기**: `node tools/make-wgbp.mjs <빌드.wasm|.wgba> <결과 롬> <출력.wgbp> --base <바탕 롬> [--label 이름] [--base <다른 판> --label … [--hidden]] [--title 글]`. 첫 `--base` 가 바탕 롬(결과 롬으로 가는 BPS + 다시 채우기 표의 출처), 다른 `--base` 는 바탕 롬으로 가는 BPS 만. `--hidden` 은 안내의 "쓸 수 있는 롬" 목록에서만 뺀다. 만든 뒤 받는 모든 롬으로 앱과 같은 코드로 `.wgba` 를 만들어 `pack-wgba` 기준과 바이트까지 같은지 확인하고, 다르면 만들지 않는다. 포트 판(롬 세 벌, 약 2분 반): 14.5MB.
- **빼고 다시 채우기**: wasm 안에서 바탕 롬과 32바이트 이상 같은 구간(포트가 되살린 원작 표 등)은 0 으로 비우고, (wasm 자리 · 길이 · 바탕 롬 자리) 표를 넣는다. 만들 때 사용자의 바탕 롬(다른 판이면 바탕 롬으로 바꾼 것)에서 채워 원래 wasm SHA-1 을 확인한다. 찾기는 32바이트 창 롤링 해시(다른 바이트 값 4개 미만인 창은 뺌), 양쪽으로 늘림, 겹치지 않게(`tools/lib/rom-ranges.mjs`).
- **형식**(little endian):

  | 위치 | 크기 | 내용 |
  | --- | --- | --- |
  | 0 | 4 | `WGBP` |
  | 4 | 2 | 머리 길이(16) |
  | 6 | 1 | 형식 판 1 |
  | 7 | 1 | 0 |
  | 8 | 4 | manifest 길이 |
  | 12 | 4 | manifest CRC32 |
  | 16 | … | manifest(JSON, utf8), 이어서 덩어리들 |

  manifest: `format` 1, `title`, `rom`{size, sha1}(결과 롬), `wasm`{size, sha1, blob}(비운 wasm), `wgba`{size, sha1}(기대 결과), `pack`{section "webgba.rom", method "zlib", impl "pako 2.1.0", level 9}, `refill`{from(바탕 롬 SHA-1), count, bytes, table}, `bases`[{sha1, size, code, revision, name, main, to, patch}]. 덩어리 `{off, len, sha1, method, size}` — off 는 덩어리 시작(16 + manifest 길이) 기준, sha1 은 저장된 바이트, method `zlib`(RFC 1950, 웹뷰 `DecompressionStream("deflate")` 로 풂)이면 size 는 푼 크기, `store` 는 그대로. 패치는 BPS(byuu, 원본·결과·패치 CRC32 포함).
- **wasm 이 아닌 짜임**으로 했다: 옛 webGBA 나 다른 실행기가 비운 wasm 을 게임으로 돌리지 않게(첫 4바이트가 `\0asm` 이 아님).
- **열기**(`index.js` `makeFromPatch`, 계산은 `js/core/wgbp.js` — node 에서도 같은 코드로 시험·확인):
  1. 읽기 → 머리·판·manifest CRC 확인. 옆에 `<이름>.wgba` 가 있으면 SHA-1 이 `wgba.sha1` 과 같을 때 그것을 그냥 열고("이미 만든 … 엽니다"), 다르면 덮어쓰기 확인.
  2. 안내 창(제목 `{title} 만들기`, 만들 파일 이름, 쓸 수 있는 롬 목록) OK → 롬 고르기(.gba·.agb·.bin·.zip). 끌어 놓기에서 `.wgbp` 와 롬(.zip 포함)을 같이 놓으면 고르기 없이 그 롬.
     - `.zip`(사용자 2026-11-01, exe·웹 같은 코드 `js/core/zip.js`): `rom_read` 를 거치지 않고 파일 그대로 넘겨 패치 작업(Worker) 안에서 푼다. 하위 폴더까지 `.gba`·`.agb`(그다음 `.bin`) 항목을 ZIP 순서로 보고, 바탕 롬 SHA-1 과 맞는 첫 항목을 쓴다. 맞는 것이 없으면 첫 항목의 이유를 "`<zip>` 안의 `<항목>`" 으로 알린다. `.gba` 없음·암호·풀 수 없는 방식(Deflate64·LZMA 등)·손상·256MB 넘는 ZIP 은 세 언어 `patch.err.zip*`. 롬 바이트가 같으므로 결과 `.wgba` 도 롬을 직접 고른 것과 바이트까지 같다.
  3. 롬 판별(SHA-1): 그대로·뒤 FF 를 16MB 까지 채운 것·32MB 에서 뒤가 FF 면 자른 것. 모르는 롬은 머리로 이유를 알린다(세 언어 `patch.err.*`): 이미 패치됨(결과 롬) · GBA 롬 아님(0xB2 = 0x96·머리 체크섬) · 같은 게임 코드인데 고쳐짐(판·SHA-1 앞 8자리) · 같은 게임 다른 언어판 · 다른 게임(머리 제목·코드).
  4. 바탕 롬까지 BPS 를 따라감(각 단계 SHA-1 = `to`) → wasm 덩어리 풀기 → 바탕 롬에서 채우기 → wasm SHA-1 → `.wgba` 묶기(pako 9) → `fileWriteBytes`(임시 파일 뒤 바꿔치기). 못 쓰면 저장할 곳을 묻는다. 기록에 SHA-1·걸린 시간, `wgba.sha1` 과 다르면 경고(파일은 올바름).
  5. 만든 `.wgba` 를 그대로 연다(상태 줄 "… 을(를) 만들었습니다(바탕 롬 이름)" + 내장 롬 · 세이브).
- 단계마다 상태 줄(롬 확인 → 패치 적용 → 게임 채우기 → 롬 묶기 → 파일 쓰기)을 그리고 넘어간다. 포트 패치는 node 로 약 2.6~6초(pako 9 압축이 약 2.3초).

## 13. 키 입력·빨리 감기 소리 (사용자 2026-10-27 "방향키가 가끔 안 먹음", "Space 빨리 감기 중 소리가 안 남")

내장 호스트(.gba·.zip 의 mGBA 코어, .wgba·.wasm 의 Web_* 포트)는 모두 `player.js` 하나를 지나므로 한 곳에서 고쳤다. 웹 빌드 페이지(iframe)는 그 페이지가 키를 받는다(그대로).

### 키 (`player.js` `keyDown`·`keyUp`·`frameKeys`, `index.js` 키 처리)
- **키마다 따로 눌림 상태**(`down`: 키 코드 → 버튼). 버튼은 그 버튼에 묶인 키 중 하나라도 눌려 있으면 눌림. 같은 버튼의 두 키(X·K = A)를 함께 누르고 하나만 떼도 버튼은 그대로(전에는 하나만 떼도 풀림).
- **짧은 누름 붙잡기**: 프레임 사이에 눌렀다 뗀 키도 다음 프레임 하나는 눌린 채로 넘긴다(`pressed`). 누른 채 프레임 사이에 뗐다 다시 누르면 다음 프레임 하나는 뗀 채로 넘겨 게임이 새 누름으로 본다(`dropped`). 붙잡기는 한 틱의 첫 프레임에만, 프레임을 하나도 돌리지 않은 틱은 다음 틱으로 넘긴다. 전에는 rAF 한 번(약 16ms) 안에 눌렀다 떼면 게임이 못 봤다(시험: 20번 중 0번).
- **초점**: 게임이 돌고 있으면 파일 목록·도구 막대 버튼에 초점이 있어도 게임 키는 게임으로 간다(목록은 그 키로 움직이지 않음, 버튼도 눌리지 않음). 설정 창·대화상자·메뉴가 열려 있으면 그쪽이 키를 받고, 열 때 누르던 키를 모두 뗀다. 창이 초점을 잃거나(`blur`) 가려지면(`visibilitychange`) 모두 뗀다. 초점이 돌아온 뒤 계속 누르고 있던 키는 다음 자동 반복 keydown 에서 다시 눌린다(전에는 반복 keydown 을 버려서 다시 눌러야 했음).
- **키 이름**: `event.code`(물리 키)로 찾는다(한글 입력기의 `key: "Process"`/229 도 그대로 됨). `code` 가 비어 오면(가상 키 입력·일부 입력기) `keyCode` → `key` 순으로 코드를 만든다(`codeOf`, 키 설정 창도 같은 함수).
- **방향키 동시 입력**(설정 `dpadMode`, 화면 이름 "설정 안함"·"대각선 입력"·"모든 입력" — 사용자 2026-11-03 문구): `latest`(기본, 누르고 있는 방향 중 나중에 누른 하나만) · `opposite`(←+→, ↑+↓ 는 나중에 누른 쪽만) · `both`(실제 GBA처럼 모두 넘김). 게임패드도 새로 누른 방향의 순서를 같이 센다. 설명서 `input.dpad` 가 있는 게임은 게임별 값(19절).
  - 기본값을 `both` → `latest` 로 바꿈(사용자 2026-10-27 결정 80 "나중에 누른 방향만으로"). 기본값은 `player.js` 의 `DPAD_DEFAULT` 한 곳. `personalization.cfg` 에 `dpadMode` 가 이미 저장된 사용자(설정 창에서 한 번이라도 SAVE 한 사람)는 그 값 그대로이고, 설정 창에서 한 번 고르면 된다.
  - 파이어레드 필드는 `FieldGetPlayerInput` 이 ↑ → ↓ → ← → → 순서로 처음 눌린 방향으로 걷는다. 그래서 `both` 에서 ↑를 누른 채 ←를 누르면 ↑를 뗄 때까지 꺾지 않는다(원작·실기 그대로). `latest` 면 누르는 대로 바로 꺾는다.
  - 방향을 아주 짧게 누르면 걷지 않고 그 방향으로 돌아서기만 하는 것도 원작 그대로(webGBA 가 고치지 않음).

### 빨리 감기 소리 (`player.js` `audioFactor`·`playAudio`)
- 전에는 빨리 감기(배수 > 1) 중 표본을 버렸다. 이제 배수만큼 표본을 묶어 평균(상자 거르개)해 실제 시간 길이로 줄여 보낸다 → 빨라진(높아진) 소리, 표본 수는 실제 시간만큼이라 대기열이 쌓이지 않는다.
- 줄이는 비율은 지난 틱들의 "돌린 프레임 시간 / 실제 시간"(감쇠 0.92 누적)을 배수 이하로 잘라 쓴다. 배수의 94% 이상이면 배수 그대로(소리 높이가 흔들리지 않게), 컴퓨터가 배수를 못 따라가면 실제 빠르기만큼만 줄여 소리가 끊기지 않게.
- 배수가 바뀌면(켜기·끄기) 묶던 표본을 버리고 워크릿 대기열을 40ms 로 줄인다(`{trim}`) → 떼면 바로 보통 소리.
- 대기열 지연 맞추기(워크릿): 1초마다 그동안의 가장 짧은 대기열을 보고, 60ms 를 넘게 남아 있었으면 30ms 만 남기고 앞을 버린다(끊김 없이 남는 지연만 없앰). 전에는 시작할 때 한 번 쌓인 표본이 빠질 길이 없어(만드는 양 = 내는 양) 앱을 켜고 처음 연 게임에서 대기열이 상한 0.25초 가까이에 붙어 있었고, 소리가 화면보다 약 0.23초 늦게 나왔다(시험 S3·S4, 처음 연 .gba 227ms, 두 번째로 연 .wgba 20ms). 상한 0.25초는 그대로.
- 설정 "빨리 감기 중 소리 끄기"(`fastMute`, 기본 끔)를 켜면 빨리 감기 동안 표본을 보내지 않는다(옛 동작).
- 워크릿에 `"fill"` 을 보내면 지금 대기열 길이(초)를 돌려준다(`player.audioFill()`, 시험용).

## 14. 마우스 (사용자 2026-10-29 "마우스 조작으로 컨트롤 가능하도록 개선(포토체스에만 허용)", 2026-10-30)

포트가 `Web_Pointer` 를 내보낼 때만 쓴다(.gba 의 mGBA 코어·옛 포트 wasm·다른 빌드는 지금과 같음). 무엇을 할지는 게임이 정한다 — 포트는 포토체스 화면에서만 읽고 다른 화면에서는 아무것도 하지 않는다.

- `player.js` `attachPointer`: 게임 캔버스의 `pointerdown`·`pointermove`·`pointerup`·`pointercancel`·`pointerleave`·`wheel`·`contextmenu`. 누를 때 `setPointerCapture` 로 캔버스 밖에서 떼도 받는다(밖이면 좌표 -1 = 게임은 "놓을 곳 없음"으로 봄).
- 좌표: 캔버스의 화면 상자(`getBoundingClientRect`, 화면 맞춤·정수 배율의 크기 그대로)에서 `floor((clientX - left) * 240 / width)`, 세로 160. 캔버스는 테두리·여백이 없고 CSS 크기만 바꾸므로 이 식 하나로 배율·여백이 빠진다.
- 이벤트마다 바로 `Web_Pointer(x, y, buttons & 7, 0)` 를 부른다(같은 값이면 부르지 않음). 포트는 프레임 사이에 온 누름·뗌·누른 자리를 모아 두었다가 다음 프레임 하나에만 보여 준다(`hack/hack_pointer.c`) — 16ms 보다 짧은 클릭도 놓치지 않는다. 키의 `pressed` 붙잡기와 같은 뜻.
- 휠: 줄·쪽 단위(`deltaMode` 1·2)는 한 번에 한 칸, 픽셀 단위는 40px 이상이면 한 칸, 그보다 작은 것(터치패드)은 모아서 40px 마다 한 칸. 게임이 마우스를 쓸 때만 `preventDefault`.
- 우클릭 메뉴: `Web_PointerWanted()` 가 1(포토체스 화면이 지난 프레임을 돌았음)일 때만 막는다. 배포 판은 웹뷰 기본 메뉴가 꺼져 있어 개발 판(`useDevelopKit`)에서만 차이가 난다.
- 일시정지·창이 초점을 잃음·설정 창(모두 `releaseAll`/`setPaused`)·다른 게임 열기: 누른 버튼을 모두 떼고 좌표 -1 을 보낸다(끌던 것은 게임이 제자리로). 그때 누르고 있던 버튼은 한 번 다 뗄 때까지 넘기지 않는다(`ptr.block`: 다시 돌아온 뒤 누른 채 움직여도 새 누름이 되지 않게).
- 창 가장자리의 크기 조절 손잡이(`.grip`, 몇 px)가 창 끝에 닿은 캔버스의 끝을 덮으면 그 몇 px 은 손잡이가 받는다(전부터 그대로).
- 시험 `tools/test/app-pointer.mjs`(목록·합격 기준은 `시험.md`).

- 연결 창 닫힘(규격 7.7, MP3 실제 호스트 확인에서 발견): 방장도 최소 인원에 닿으면 "연결됨 · n/m" 을 보이고 1초 뒤 창을 닫는다(방 코드·근처 방·연결 코드 모든 길, 최소 = 최대 포함). 최대 인원 전이면 방 코드 받기는 창이 닫힌 뒤에도 계속(가득 차면 멈춤), 연결 코드로 더 초대하려면 상태 메뉴 초대 코드로 창을 다시 연다(다시 연 창은 저절로 닫지 않음).
- 설정: 멀티플레이 켜기(끄면 다음에 연 게임에 `Web_NetHost`·`webgba.net` 을 주지 않음, 게임 도중이면 진행 중인 요청·세션을 CANCEL)·닉네임(비우면 "플레이어 + 숫자 4개", 12자). 웹 = 설정 시트, exe = 설정 창 일반 › 멀티플레이(SAVE).

## 20. GB·GBC 실행 (사용자 2026-11-02 결정 146 "webGBA가 gb 파일이나 gbc 파일도 읽을 수 있게", v0.5.1)

내장 mGBA 0.10.1 이 GB·GBC 를 지원하지만 코어 빌드에서 GB 코어를 꺼 두었다(`-DM_CORE_GB=OFF`). 같은 코어 하나로 GBA·GB·GBC 를 실행한다. 1차 제외 = 슈퍼 게임보이 테두리·색, GB 통신 케이블, 흑백 GB 색 팔레트 선택.

| 항목 | 결정 |
| --- | --- |
| 코어 | `-DM_CORE_GB=ON`(Docker emsdk 4.0.10 그대로). wasm 580,584 → 725,311바이트(+144,727, 1MB 웹 빌드 한도 안). 가져오기 목록 그대로, 내보내기 3개 추가(`Web_GetScreenWidth`·`Web_GetScreenHeight`·`Web_GetSystem`) |
| 기종 판별 | 확장자가 아니라 롬 머리. 코어 = mGBA `mCoreIsCompatible`(GBA 머리 먼저 → GB 머리, 모르는 롬은 기존대로 GBA 코어). 화면 쪽 = `rom-kind.js` `romKind`(GBA: 3 = 0xEA 이고 0xB2 = 0x96 또는 0x04~0x9F 가 모두 0 — mGBA `GBAIsROM` 과 같음, GB: 0x104 로고 48바이트의 CRC32 = 0x46195417 — 로고 내용은 코드에 두지 않음). 실행할 때의 화면·키는 코어가 알려 준 `Web_GetSystem` 을 따르고(`systemKind`), 웹 보관함 종류가 다르면 그 값으로 고친다 |
| GBC 전용·겸용 | 0x143 비트 7 = GBC 모드(mGBA 자동 판별과 같음), 비트 6 까지 = GBC 전용, 비트 7 만 = GB·GBC 겸용. 글: "GB"·"GBC 전용"·"GB·GBC 겸용"(`rom.*`) — exe 상태 줄, 웹 라이브러리·첫 화면 최근 줄의 종류 글 |

| 화면 | 160×144, 화면 칸 10:9(`GB_SCREEN` — 19절 `display.aspect` 화면 칸 비율 그대로 재사용, 늘리기 없음). 코어 화면 버퍼는 GB 일 때 256 폭 줄(SGB 최대 256×224 자리), `Web_GetFramebuffer` 가 지금 크기만 RGBA 로 묶는다. GBA 는 240 폭 그대로(같은 바이트) |
| 색 | GBC 모드 = 게임 팔레트. 흑백 GB = mGBA 기본 회색 4단계(`gb.pal`·`gb.colors` 설정 안 씀) |
| 키 | GB 비트 0~7 = GBA 와 같은 자리(A·B·SELECT·START·→·←·↑·↓), 코어가 `keys & 0xFF`. 버튼 목록 `GB_LAYOUT`(GBA 8버튼, `system: "gb"`): 터치 L·R 자리 숨김, 게임패드 L·R 배치 없음, 조작법 8개 + 빨리 감기. 키 값은 앱 전체 GBA 키를 그대로 쓰고 exe 키 설정 창은 8개 + 빨리 감기와 안내(`cfg.keys.gb`), 저장하면 L·R·C·D 키는 그대로 둔다. 반대 방향 동시 입력은 GBA 코어 기본과 같게 코어가 허용(`allowOpposingDirections`)하고 거르기는 호스트 설정(13·19절) |
| 세이브 | 배터리 세이브 = `.gba` 와 같은 자리·이름(exe 롬 옆 `<롬 이름>.sav`, 웹 보관 id). MBC3 RTC 는 mGBA 가 세이브 끝 48바이트(초·분·시·일 + 래치 + 유닉스 시각, VBA-M 형식)에 함께 쓴다 → 다시 열면 닫혀 있던 시간만큼 진행. 시계 = 호스트 `Date.now()`(GBA RTC 와 같은 길) |
