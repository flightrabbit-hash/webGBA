# 주석 — 배포 파일의 "왜"

배포되는 html·js·css 에는 주석을 두지 않는다(아비터 규칙). 지켜야 할 까닭은 파일 → 이름으로 여기에 적는다.

## src-bundle/src/js/core/web-host.js

- `inspectModule`: 가져오기가 모두 아는 함수이고 필수 내보내기(`memory`·`Web_Init`·`Web_RunFrame`·`Web_GetFramebuffer`)가 있어야 내장 호스트를 쓴다. 모르는 함수가 하나라도 있으면 글루 .js 가 필요한 빌드로 본다(설계 6절).
- `imports` → `invoke_*`: emscripten 표준 모양. 숫자 예외(longjmp 의 `Infinity`)만 삼키고 `setThrew(1, 0)`, 그 밖의 예외는 다시 던진다. 스택은 `_emscripten_stack_restore` 로 되돌린다.
- `emscripten_resize_heap`: 메모리를 늘린 뒤 뷰가 바뀌므로 `u8`·`dv` 는 버퍼가 바뀌었는지 보고 다시 만든다.
- `fd_read`·`fd_close`·`fd_seek`·`fd_sync`: 파일을 쓰지 않으므로 오류 번호만 돌려준다(mGBA 코어는 `host_stubs.c` 로 파일 함수가 불리지 않게 막아 둠).
- `placeRom`: 롬을 코어에 넘기는 **유일한 곳**. `Web_RomBuffer` 가 있으면 그 자리, 없으면 포트처럼 0x08000000 고정. 롬을 묶은 `.wgba` 도 풀린 롬이 여기로 온다.
- `readEmbeddedRom`(사용자 2026-10-27, 설계 8절 "롬을 묶은 `.wgba`"): 이미 컴파일한 모듈의 `customSections` 에서 꺼내므로 파일을 다시 읽지 않는다. 여럿이면 마지막(묶는 도구는 하나만 남기지만, 손으로 덧붙인 것이 이기게). 머리 길이 칸만큼 건너뛰어 뒤에 칸이 늘어도 읽는다. 형식 판·방식을 모르면 "손상" 이 아니라 "새 판으로 바꿔 주세요" — 새 도구로 묶은 파일을 옛 앱이 열 때를 구분하려고. SHA-1 은 `crypto.subtle`(`*.localhost` 는 보안 출처라 됨, Node 시험도 같은 전역). 풀기는 `DecompressionStream("deflate")` = zlib(RFC 1950). 실패 문장의 이유는 `t()` 로 바로 넣는다(키를 코드에 그대로 적어야 `i18n-keys.mjs` 가 찾음).
- `readRomPayload`(S2, 2026-10-31): 롬 구획 내용(WGRM 1) → 롬. 옛 `.wgba` 는 `readEmbeddedRom` 이 모듈의 구획을 넘기고, 새 `.wgba` 는 목차의 `rom` 조각(파일 바이트의 subarray)을 그대로 넘긴다 — 같은 확인·같은 문장. `knownImport` 는 `webgba.v1`(규격 4.1.2, 이 규격을 아는 호스트 표시)을 받고 `imports()` 는 빈 함수를 준다. `bootHost`·`reset` 은 롬이 null 이면 놓지 않는다(설명서 `rom.required: false` 인 ① 게임).
- `placeSave`: 모두 0 이거나 모두 FF 면 세이브가 없는 것으로 본다(포트 app.js 와 같음). 넣는 크기는 `saveCapacity` 까지(포트 512KB). 더 짧은 옛 세이브(포트 128KB)는 앞에 넣는다 — 게임이 읽어 큰 형식으로 옮긴다.
- `saveCapacity`: 128KB 와 `Web_GetSaveSize` 중 큰 값. mGBA 코어는 지운 직후 128KB, 게임 중에는 그 게임 세이브 크기(128KB 이하)라 늘 128KB, 포트는 PC 박스 30 판부터 512KB.
- `reset`: `Web_Reset` 이 없으면(포트) 같은 모듈로 인스턴스를 새로 만들고 지금 세이브를 다시 넣는다. 포트 app.js 가 재시작을 페이지 새로 고침으로 하던 것과 같은 결과.

## src-bundle/src/js/core/wgbp.js (`.wgbp`, 사용자 2026-10-28, 설계 8절)

- 화면·i18n 을 쓰지 않는 계산만 둔다. 같은 파일을 node 도구(`make-wgbp.mjs` 자기 확인, `pack-wgba.mjs` 압축, `tools/test/wgbp-node.mjs`)가 그대로 import 해서, 앱이 만드는 `.wgba` 와 도구가 만드는 `.wgba` 가 같은 코드에서 나오게 한다. 브라우저·node 모두에 있는 전역만 쓴다(`crypto.subtle`, `DecompressionStream`, `Blob`, `Response`, `TextEncoder`).
- `WgbpError`: 화면 글 대신 코드(`code`)와 값(`params`)만 담는다. 문장은 `index.js` 의 `patchError` 가 `patch.err.<code>`·`patch.why.<why>` 로 고른다(이 두 키 무리는 코드가 이름을 만들어 쓰므로 `i18n-keys.mjs` 의 "표에만 있는 키" 에 나온다).
- `romPayloadFrom`: SHA-1 을 바깥에서 받는다 — `pack-wgba.mjs` 는 node `crypto` 로 같은 값을 동기로 만들어 넘겨 옛 동기 API(`pack`·`makePayload`)를 그대로 둔다. 압축은 pako `deflate(rom, { level })`(zlib 머리, 표준 zlib 1.2.13 과 같은 바이트).
- `bpsApply`: 끝 12바이트 CRC 세 개를 모두 본다. 메타 길이를 읽은 뒤 건너뛸 때 `pos.i += readNumber(...)` 로 쓰면 왼쪽 값을 먼저 읽어 길이 칸만큼 덜 건너뛴다 — 꼭 따로 읽어 더한다. TargetCopy 는 겹쳐 복사(반복 무늬)가 있어 한 바이트씩.
- `findBase`: 정식 덤프가 아닌 흔한 모양(뒤 FF 를 자른 것, 32MB 로 늘린 것)도 SHA-1 이 맞으면 받는다. 모르는 롬은 머리로만 이유를 고른다 — 롬 내용(닌텐도 로고 등)을 코드에 두지 않으려고 0xB2 = 0x96 과 머리 체크섬(0xBD)만 본다.
- `buildGame`: 사슬(`bases[].to`)을 따라가다 바탕 롬(`refill.from`)이 나오면 그 바이트로 wasm 을 채운다. 사슬이 `bases` 수보다 길면 망가진 것으로 본다(고리 방지).
- `findBaseIn`(2026-11-01 ZIP): 롬 자리에 후보 배열(`[{ name, read }]`)이 오면 차례로 읽어 `findBase` 가 받는 첫 것을 쓴다. 모두 거절이면 **첫 후보**의 오류에 `params.entry` 를 붙여 던진다(뒤 후보의 이유는 버림 — 고른 ZIP 의 첫 롬 기준으로 알리려고). 이 파일은 ZIP 을 모른다(후보는 `zip.js` 가 만들고, `zip.js` → `wgbp.js` 한 방향만 가져와 순환이 없음).

## src-bundle/src/js/core/zip.js (`.wgbp` 패치의 롬 `.zip`, 사용자 2026-11-01)

- 새 라이브러리 없이 중앙 디렉토리를 직접 읽고 Deflate 는 pako `Inflate`(raw)로 푼다. 웹 일반 열기(`extractRom`)와 패치(`romChoices`)가 같은 코드. exe 일반 열기(.gba 대신 .zip 을 열 때)는 지금처럼 Rust `zip` 크레이트(`files::read_rom`).
- 오류는 `ZipError`(`WgbpError` 의 하위) — Worker 가 `instanceof WgbpError` 로 코드·값만 넘기므로 화면 쪽은 `patch.err.<code>` 로 그대로 고른다. 코드: `zipNoRom`·`zipEncrypted`(flag bit 0, 방식 99 = AES)·`zipMethod`(`params.method` 이름)·`zipCorrupt`(`params.why` 는 기록용)·`zipTooBig`, 항목이 32MB 를 넘으면 `romTooBig`.
- 크기: 항목은 `MAX_ROM`(32MB)까지 — 적힌 크기로 먼저 거르고, 풀 때도 적힌 크기를 넘는 순간 멈춘다(`onData` 에서 던짐, 압축 폭탄 방지). 풀린 길이·CRC-32 가 적힌 값과 다르면 손상. ZIP 파일 자체는 `ZIP_MAX`(256MB)까지 — 읽기 전에 부르는 쪽이 크기를 본다(exe `fileStat`, 웹 `File.size`).
- `zipFile`: 이름이 `.zip` 인데 `PK` 머리가 아니면(다른 압축을 이름만 바꾼 것 등) "GBA 롬이 아님" 대신 손상 ZIP 으로 알린다. `romChoices` 는 머리로만 ZIP 을 알아본다(GBA 롬 첫 4바이트는 ARM 분기 명령이라 `PK\3\4` 일 수 없음).
- ZIP64(끝 레코드·추가 칸 0x0001)·데이터 설명자(크기는 중앙 디렉토리 값)·`\` 구분자를 받는다. 여러 디스크는 손상으로 본다.
- 항목 이름: UTF-8(flag bit 11 이 없어도 맞는 UTF-8 이면 그대로), 아니면 `euc-kr`(옛 한국어 Windows 압축). 화면 안내·기록에만 쓰고, 고르기는 ASCII 확장자로만 한다.
- 건너뛰는 항목: 폴더(`/` 로 끝남), macOS 덧붙이(`__MACOSX/`, `._*`) — 이름이 `.gba` 로 끝나 첫 후보를 가로채지 않게.
- `extractRom`(웹 일반 열기): 옛 웹 `zip.js` 와 같은 고르기(가장 큰 것, `.gba`·`.agb` 먼저).

## src-bundle/src/js/vendor/pako.js

- pako 2.1.0 `dist/pako.esm.mjs` 를 고치지 않고 이름만 바꿨다(`.mjs` 도 서빙되지만 다른 js 와 같은 확장자로). 안의 주석·저작권 줄은 원저작자 것이라 그대로 둔다(이 파일만 "배포 파일에 주석 없음" 규칙의 예외). 바꾸면 `.wgba` 압축 바이트가 달라질 수 있으므로 판을 올릴 때는 `make-wgbp` 의 자기 확인과 `app-wgbp` 시험을 다시 한다.

## src-bundle/src/js/app/player.js

- `FRAME_MS`·`MAX_FRAMES_PER_TICK`: 포트 app.js 와 같은 값(59.7275Hz, 한 번에 8프레임). 밀린 시간이 8프레임을 넘으면 버려 늦게 따라잡느라 빨라지는 일이 없게 한다.
- `WORKLET`: 포트 app.js 의 고리 버퍼와 같은 방식. 0.25초를 넘게 쌓이면 앞을 버려 지연이 늘지 않게 한다. `"clear"` 는 상태 불러오기·일시정지·재시작 때 지난 소리를 지운다.
- 빨리 감기 중 소리(2026-10-27, 설계 13절): 늘어난 표본을 그대로 내면 버퍼가 넘치므로 배수만큼 묶어 평균해 실제 시간 길이로 줄인다(`playAudio`). 비율은 실제로 따라간 빠르기(`audioFactor`·`notePace`)라 컴퓨터가 배수를 못 따라가도 끊기지 않는다. 배수의 94% 이상은 배수 그대로 — 틱마다 돌린 프레임 수(3·4)가 흔들려도 소리 높이가 떨리지 않게. `fastMute` 를 켜면 옛 동작(버림).
- 키 상태(2026-10-27): 버튼 비트 하나만 들면 같은 버튼의 두 키 중 하나를 뗄 때 같이 풀리고, 프레임 사이의 짧은 누름이 사라진다. 그래서 키 코드마다 `down` 에 들고, 프레임 사이의 누름·뗌은 `pressed`·`dropped` 로 한 프레임 붙잡는다. `dropped` 는 지난 프레임에 보낸 값(`sent`)에 그 버튼이 있었을 때만 — 처음 누른 짧은 누름까지 지우지 않게.
- `dirStamp`: 방향마다 마지막으로 새로 눌린 순번. `dpadMode` 의 `opposite`·`latest` 가 "나중에 누른 쪽"을 고를 때 쓴다. 게임패드는 틱마다 새로 눌린 방향만 센다(`notePad`).
- `setKeys` 는 모든 키를 뗀다 — 키 설정을 바꾸는 동안 눌려 있던 키가 옛 묶음으로 남지 않게.
- `WORKLET` 의 `"fill"`: 대기열 길이를 돌려준다(`audioFill`, 시험 도구가 소리가 밀리는지 볼 때).
- iOS 소리(2026-10-30, 최신 아이폰 무음 제보): iOS 의 Web Audio 는 기본이 ambient 라 무음 모드(동작 버튼·제어 센터의 무음 포함)면 소리가 나지 않는다. `syncAudioSession` 이 AudioContext 를 만들기 전에 `navigator.audioSession.type`(Safari 16.4+)을 `playback` 으로, 소리를 끄거나 크기 0 이면 `ambient` 로 둔다(끈 동안 다른 앱 음악을 멈추지 않게). API 가 없는 Chrome·안드로이드·WebView2 는 아무것도 바꾸지 않는다. playback 이라 게임 소리가 켜져 있으면 다른 앱 음악은 멈춘다.
- 잠금 풀기·복구: `ensureAudio` 는 동작 안에서 `new AudioContext` 직후 바로 `resume()`(addModule 을 기다리기 전). 켜지지 않은 상태(`suspended`·iOS `interrupted`)는 동작마다 `wakeAudio(true)`(1표본 무음 + resume), `statechange`·화면 복귀(`resumeAudio`)는 동작 없이 한 번 시도. `watchAudio`(틱마다): running 인데 `currentTime` 이 2초 멈추거나, 동작 안에서 깨웠는데 2초 넘게 안 켜지면 `stuck` → 다음 동작에서 닫고 새로 만든다(WebKit 291892·276016 류). 화면이 0.5초 넘게 멈췄던 틱은 세지 않는다. 소리가 늦게 준비되면 그때 `setAudioRate` 를 다시 건다.
- `queueSave`: 게임이 세이브를 다 쓴 신호(`takeSaveDirty`) 뒤 1초 기다렸다가 한 번만 쓴다(사용자 2026-10-27 "약 1초"). 게임은 세이브를 여러 프레임에 걸쳐 쓰므로 마지막 신호에서 다시 센다. 일시정지·재시작 전에는 `flushSave` 로 마저 쓴다.
- `flushSave({ final })`: 닫을 때(`stop`)는 밀린 것이 없어도 코어 세이브가 `saveBase`(연 직후·마지막으로 쓴 내용)와 다르면 쓴다 — 신호를 놓친 쓰기도 잃지 않게. 같으면 쓰지 않아, 게임을 켜 둔 채 밖에서 넣은 `.sav` 를 닫기가 덮어쓰지 않는다.
- `start` 에서 `takeSaveDirty()` 를 한 번 비운다 — 세이브를 넣으며 생긴 신호로 열자마자 같은 내용을 다시 쓰지 않게.

## src-bundle/src/js/pages/index.js

- `makeFromPatch`(`.wgbp`, 설계 8절): `openPath` 안에서 부르고, 만든 `.wgba` 경로를 돌려주면 `openPath` 가 그 경로로 이어서 연다(최근 연 파일·같은 폴더 목록의 선택도 `.wgba`). 옆 `.wgba` 가 이미 같은 것이면 롬을 다시 묻지 않는다 — `.wgbp` 를 지우지 않고 계속 두 번 눌러 여는 사람도 매번 롬을 고르지 않게. 단계마다 `paint()`(다음 그리기 + 한 틱)로 상태 줄을 먼저 그린다(압축 약 2초 동안 화면이 멈춘 듯 보이지 않게). 시험은 `openPath(path, { patchRom })` 로 고르기 창을 건너뛴다(끌어 놓기에서 `.wgbp` 와 롬을 같이 놓은 것과 같은 길). 고른 롬이 `.zip` 이면 `rom_read`(Rust, 안의 첫 롬)를 거치지 않고 `readZip`(크기 확인 → `fileReadBytes` → `zipFile`)으로 파일 그대로 넘긴다 — 여럿 중 바탕 롬과 맞는 것을 고르는 일은 패치 작업(`zip.js` `romChoices`)이 한다.

- `importSave`: 받는 크기 — mGBA 코어 게임 128KB, 내장 호스트로 도는 웹 빌드는 그 호스트의 `saveCapacity`(포트 512KB), 원래 페이지로 여는 웹 빌드는 1MB(`web.rs` `/save` 한도). Rust `save_import` 가 옆 `.sav` 를 그 내용으로 직접 덮어쓰고(백업 없음) 게임을 다시 연다. 덮어쓰기 전에 `player.stop` 이 지금 세이브를 한 번 써 두므로, 가져오기가 실패해도 옆 파일은 방금까지의 진행이다.
- `importSave(source)`·`exportSave(target)`: 문자열 경로를 받으면 파일 고르기 창을 건너뛴다(시험 훅 `__WEBGBA_TEST__` 용 — `window.__TAURI__.core` 가 얼어 있어 시험이 `pick_file` 을 가로챌 수 없음). 메뉴는 인자 없이 부르므로 늘 창을 띄운다. 가져오기 확인 창은 그대로 뜬다.
- `openWasm` 새 `.wgba`(S2, 2026-10-31): 목차가 있으면 `readWgba`(조각 SHA-256 확인) → 못 여는 것(script·화면 크기·needs) 안내 → `compileCode`(code 조각만, 롬·그림은 엔진 메모리 밖) → rom 조각을 `readRomPayload`. 내장 호스트로만 연다(페이지·글루 길 없음, 모르는 가져오기면 `wgba.badImports`). 상태 줄·창 제목은 "<이름> <버전>", 정보 창 맨 위에 게임 이름·버전·id·만든 이·빌드 앞 8자리. 세이브는 지금처럼 연 파일 옆 `<이름>.sav`(게임 id 와 관계없음).
- `openWasm`: `.wgba`·`.wasm` 공통. 먼저 첫 4바이트(`\0asm`)를 보고, 그다음 `web_inspect`(여기서 `.wasm` 때의 상태 슬롯 폴더를 이어받음) → `openSave`. 열기 순서는 설계 6절(내장 호스트 → 페이지 → 글루 → 안내). 페이지·글루로 갈 때는 컴파일한 모듈을 버린다(iframe 이 따로 불러옴). 페이지·글루는 `/save` 로 옆 파일을 직접 읽고 쓰므로 `openSave` 를 부르지 않는다. 롬이 묶여 있으면(`readEmbeddedRom`) 페이지·글루로 가더라도 먼저 풀어 확인한다 — 망가진 구획을 iframe 안의 알 수 없는 오류 대신 상태 줄 문장으로 알리려고(페이지의 `/rom` 은 Rust 가 다시 풀어 줌). 이때 `resolveWebRom`·`webSetRom` 을 부르지 않아 고르기 창이 뜨지 않는다.
- `openSave`: `save_path`(상태 줄에 보일 파일 이름) → `save_read`. 옆 파일을 읽지 못하면 오류로 열기를 멈춘다(빈 세이브로 시작해 덮어쓰지 않게).
- `hidePaths`·`PATH_IN_TEXT`: 상태 줄에 들어가는 문장 속 `X:\…\이름` 을 이름만 남긴다. 이름 안의 공백·괄호(`My Game (E).gba`)를 지키려고 끝을 `: `·` · `·` — `·`, `·문장 끝으로만 잡는다(`tools/test/hide-paths.mjs`).
- `labels`: 목록에서 같은 이름이 둘 이상일 때만 폴더 이름 하나를 붙인다.
- `loadRoot`: 루트(지금 게임의 폴더)만 읽고 `.gba`·`.wgba`·`.wasm` 만 남긴다. 폴더 줄·위 폴더 이동은 없다(사용자 2026-10-26).
- `toggleRail`: 접힘은 `html.is-rail-collapsed` 한 곳에서 막대·패널을 함께 숨긴다(화면을 덮지 않고 자리를 비움). 패널 버튼을 누르면 펴진다.
- `resolveWebRom`: 기억한 롬 → Rust 짐작(`web::guess_rom`, 설정 `webRom` 이름 → `<빌드 이름>.gba` → 같은 폴더의 하나뿐인 `.gba`) → 대화상자. 페이지·글루 모드에서는 묻지 않는다(페이지가 스스로 롬을 고르게 둠). 기억한 롬이 설정 이름보다 앞 — "롬 지정…"으로 빌드마다 고른 것이 전체 설정보다 구체적이어서. 롬 이름은 코드에 박지 않는다(2026-10-27 공개 전 정리, 옛 `KNOWN_ROM_NAMES` 없앰). 같은 폴더에 `.gba` 가 여럿이면 위 폴더로 가지 않고 묻는다 — 엉뚱한 롬을 조용히 고르지 않게.
- `DPAD_DEFAULT`(player.js): 방향키 동시 입력 기본값 `latest`(사용자 2026-10-27). 저장값이 없을 때만 쓰인다.
- `dpadFor`·`gameDpadPatch`(player.js, 결정 145): 설명서 `input.dpad` 가 있는 게임만 게임별 값(`prefs.gameDpad[게임 id]` → 설명서 값), 없으면 전체 `dpadMode`. 게임별 값이 설명서 값과 같으면 지운다(`gameKeys` 와 같은 규칙 — 설명서 값이 바뀌면 따라가게). exe·웹이 같은 함수를 써서 저장 모양이 같다.
- `applyInput`: 버튼 목록을 바꿀 때 방향 처리도 다시 정한다(게임을 열고 닫을 때 한 곳). 닫을 때 `applyInput(null)` 은 버튼이 GBA 그대로여도 `input.dpad` 가 있으면 부른다(전체 설정으로 되돌리려고).
- `applySettings`: 설명서가 방향 값을 정한 게임이 실행 중이면 방향 값은 `gameDpad` 로만 가고 `dpadMode` 는 이전 값을 그대로 다시 쓴다(설정 창 한 줄이 게임 값과 전체 값을 함께 바꾸지 않게).
- 설정 훅 `hint`: 방향 줄 설명을 게임 전용 안내(`cfg.dpadMode.game`)로 바꾼다. 새 줄을 만들지 않고 같은 줄을 쓰는 까닭은 값이 하나뿐이라서(게임이 정했으면 게임 값, 아니면 전체 값).
- `openFrame`·`focusFrame`: iframe 이 다 불러오면 초점을 줘서 실제 키 이벤트가 페이지로 가게 한다. 본 창에 초점이 남아 있을 때는 `forwardKey` 로 넘긴다.
- `stepGame`: 아비터 `stepPhoto` 와 같은 모양(폴더를 다시 읽고, 같은 종류만 한국어 이름순, 끝에서 처음으로 돌아감).
- `openDropped`: 아비터와 같은 모양(놓은 경로를 하나씩 `fileStat`). 열 수 있는 첫 파일 하나만 열고, 폴더는 열지 않는다(폴더 이동 기능을 뺐으므로).
- `hotkey`: 브라우저 가속키는 Rust 가 꺼 두었다(F5·Ctrl+R 이 새로 고침이 되지 않게). F1~F9 는 게임이 있을 때만 상태 키.
- 키 처리에서 `event.repeat` 을 따로 보는 까닭: 길게 누를 때 OS 반복 입력이 게임 키 상태를 흔들지 않게(이미 눌린 키면 아무것도 안 함). 다만 초점을 잃었다 돌아와 뗀 상태로 바뀐 키는 반복 입력에서 다시 누른다(2026-10-27).
- 게임이 돌 때는 파일 목록에 초점이 있어도 게임 키를 먼저 받아 `preventDefault` 하고, 목록의 keydown 듣개는 `defaultPrevented` 면 아무것도 안 한다 — 목록을 한 번 누른 뒤 방향키가 목록으로만 가서 "게임이 안 먹는" 일이 없게(2026-10-27). keyup 도 게임 키면 `preventDefault`(초점 버튼이 Space·Enter 로 눌리지 않게).
- `openSettings`·`openDialog` 는 누르던 키를 모두 뗀다 — 열려 있는 동안은 keydown 이 게임에 가지 않으므로, 열기 전에 누르던 방향으로 계속 걷지 않게.
- `codeOf`(player.js): `event.code` 가 비어 오는 키(SendInput 으로 만든 가상 키·일부 입력기)는 `keyCode`·`key` 로 코드를 만든다. 한글 입력기의 `"Process"`/229 는 `code` 가 그대로 와서 원래 됐다.
- `window.__WEBGBA_TEST__`: `useDevelopKit: true` 일 때만 만든다(시험 도구가 CDP 로 부름).
- 아이콘 주소는 `/icons/…` 절대 경로. 인라인 `--icon: url(…)` 을 상대 경로로 쓰면 css 폴더 기준으로 풀려 그림이 안 나온다.

## 화면 맞춤 (`index.js` 의 `layoutScreen`, 사용자 2026-10-27)

- 화면 크기·비율은 `screenOf(설명서)`(`wgba-read.js`): `aspect` = `display.aspect`(약분) → 없으면 화면 버퍼 비율, `stretch` = 두 비율이 다름(결정 143). 버퍼와 같은 비율을 적은 설명서는 `stretch` false 라 현재와 같은 처리.
- `stretch` 이면 세로를 먼저 정한다: 배율 = min(너비/(세로 × 표시 비율), 높이/세로), 정수 배율이면 내림 → 세로 = 버퍼 세로 × 배율(정수 배면 행 높이가 모두 같음), 가로 = 세로 × 표시 비율(영역 너비 이하). 가로는 비정수 배라 열 폭이 1 기기 픽셀씩 다를 수 있지만 보간하지 않는다(사용자 "픽셀 보간 없음"). `stretch` 가 아니면 아래 옛 식 그대로.

- 기본은 오른쪽 영역(`#stage`)에 맞춘다: 배율 = min(너비/240, 높이/160), 비율 240:160 유지. 정수 배율은 `prefs.scaleMode === "integer"` 일 때만(기본으로 켜 두면 422px 영역에서 1배 240px 로 내려가 "너비에 안 맞는" 화면이 됨).
- 옛 키 `integerScale` 은 보지 않는다 — 처음 실행 때 씨앗(personalization.cfg)으로 들어간 값이라 사용자가 고른 것이 아니다.
- 높이는 너비 × 160/240 으로 계산해 비율이 1px 도 어긋나지 않게 한다(늘리지 않는 게임).
- 영역 크기가 0 이면(창이 아직 숨김) 건너뛴다. `ResizeObserver(#stage)` 와 `window resize`, `showView` 가 다시 부른다.

- 자리 잡기: 방 기록의 Offer 번호 q 마다 `c:<x>:<q>` 를 `SET NX` — 둘이 같은 Offer 를 잡으면 늦은 쪽은 `wait`(방장이 다음 Offer 를 올리면 들어감), 마지막 자리면 `full`. 마지막 자리를 잡은 유저가 근처 목록 칸을 비운다(방장 요청 한 번을 아낌). 자리를 잡고 20초 안에 Answer 가 없으면 방장이 새 Offer 로 바꾼다.
- 근처 묶음: HMAC(날짜별 비밀값, IPv4 전체·IPv6 앞 /64) 앞 12바이트. 비밀값은 환경 변수를 늘리지 않으려고 Redis `s:<날짜>` 에 `SET NX EX 2일` 로 두고 함수 메모리에 캐시. 근처 목록은 묶음마다 고정 칸 10개(`n:<묶음>:0~9`, 방 코드 % 10 칸부터)라 `MGET` 한 번으로 읽는다.
- 토큰은 저장하지 않는 HMAC(날짜 + 방 코드·방 난수 x·묶음·칸 / x·q): 확인에 Redis 읽기가 없다. 방장 토큰에 묶음·칸을 넣어 남의 근처 목록에 쓰지 못하게 한다.
- 제한: 쓰기(방 만들기·바꾸기·들어가기·답)는 Redis `INCR`(분마다 열쇠, 첫 번째만 EXPIRE)로 근처 묶음마다 1분 60회, 읽기(근처·받기·방 상태)는 함수 메모리로 같은 한도(명령을 쓰지 않음). 출처는 `webgba.vercel.app`·exe 앱 화면(`http://ui.localhost`)·같은 출처만 — 게임 틀(`game.*`·`null`)은 거부. 본문은 `text/plain` 으로 보내 사전 요청(OPTIONS)을 없앤다.
- 클라이언트: 서버 오류(Upstash 한도·장애·오프라인·429)면 방 만들기는 이미 만든 Offer 로 연결 코드 화면(MP1)으로 넘어가고, 근처 방·코드로 들어가기는 "인터넷 없이 연결(코드·QR)" 을 보여 준다. 방장 받기는 창이 열려 있거나 최소 인원 전일 때만(창을 닫은 뒤 계속 부르지 않게). 웹 Service Worker 는 `/api/` 를 건드리지 않는다(네트워크만).
- 연결 창(`net-window.js`): 첫 화면 = [참가하기 | 방 만들기] 탭(아래 "연결 창 B 탭형" 절). 열린 방(같은 호환 키·용도 = 들어가기, 다른 호환 키 = "다른 버전" 흐림·"들어갈 수 없음", 다른 용도는 숨김)은 참가 탭이 보이는 동안 5초마다(실패하면 10초, 새로 고침 단추 = 바로).
- exe 이름 줄(kit `entry`, `.net-entry`): 인터넷 없이 연결 화면·다시 연결 화면의 버튼을 한 줄에 하나씩, 좌측 현재 언어 이름("방 만들기"·"참가하기") + 우측 대문자 영어 버튼(CREATE·JOIN)으로 그린다. 버튼 글자만 있으면 사용자가 방 만들기를 찾지 못하고 OPEN 을 방 열기로 보고 연결 코드 화면으로 갔다(사용자 2026-11-02). 웹 kit 은 `entry` 가 없어 버튼 글자 그대로 한 줄(현재 언어 글자라 이름이 겹침).

## 인터넷 연결 · 게임별 연결 서버 (`lan.js`·`ice.js`, 사용자 2026-11-02 결정 106·142)

- 설정 `netWan`(기본 끔) 을 켠 기기만 STUN 을 쓴다. 기본 서버는 공개 STUN 두 곳(구글·클라우드플레어, 한쪽이 막혀도 되게). TURN 은 webGBA 가 운영하지 않는다(비용·중계 책임) — 게임이 `iceServers` 로 지정한 경우만.
- 코드 머리 바이트 비트 6 = "이 기기는 인터넷 연결 켬". 받는 쪽은 상대가 켰을 때만 자기 공인 후보를 넣는다 → 한쪽만 켜면 아무도 공인 IP 를 보내지 않는다(같은 와이파이만). 비트 7 은 예약(켜져 있으면 `version` 오류 — 다음 형식이 옛 webGBA 에서 엉뚱하게 읽히지 않게).
- 후보 칸: 1 = mDNS, 4·6 = host(망 안 또는 공인), `0x10|4·6` = srflx, `0x20|4·6` = relay. 같은 후보는 한 번만, 공인 후보는 4개까지, 망 안 후보를 먼저(합 8개). 되살릴 때 srflx·relay 는 `raddr 0.0.0.0 rport 0`(브라우저가 가리는 값과 같은 모양).
- relay 주소는 사설이어도 받는다 — TURN 서버 주소이지 사용자 주소가 아니고, 회사 안 TURN 이 사설 주소를 쓴다. 루프백·멀티캐스트는 늘 버림.
- 켠 기기는 srflx·relay 쌍도 받는다(`pairOk`). 끈 기기는 host·prflx 쌍만(아래 "참가 확인 READY" 절).
- 모으기 기다림: 끔 = 망 안 후보 + 1.2초(최대 3초), 켬 = 망 안 후보와 srflx 가 모두 나온 뒤 0.4초(srflx 만 나오면 1.5초, 망 안 후보만 나오면 2.5초, 최대 4초) — mDNS 이름 등록이 STUN 응답보다 늦는 기기에서 srflx + 0.4초로 끝내면 코드에 망 안 후보가 빠져 같은 와이파이인데 공유기 헤어핀에 기대게 된다(2026-11-03 사용자 PC 기록: 켬 상태 3회 ICE 실패, 끔 상태는 연결까지 감 — 휴대폰 쪽 원인은 기록이 없어 추정), TURN 이 있으면 relay + 0.3초(최대 6초). ICE 재시작 뒤에는 이미 "complete" 인 상태를 믿지 않는다(`fresh`, 새 후보가 아직 안 나왔을 수 있음).
- `ice.js` `IcePlan`: 설명서 목록을 열 때 한 번 검사하고, 접속 정보(`credentialUrl`)는 연결 PC 를 만들 때만 받는다(쿠키·리퍼러 없음, 리디렉션 거부, 5초·8KB, 응답의 서버 주소는 무시 — 설명서 주소만 씀). 받은 정보는 `ttl` 의 80%(최대 10분) 동안 다시 쓰고, ICE 재시작 전에는 `setConfiguration` 으로 새 정보를 건다. 실패한 항목만 빼고 연결하며 창에 안내(`iceFailed`).
- 연결 창의 "이 게임의 연결 서버: 도메인" 은 설명서 주소의 호스트 이름만(경로·접속 정보는 보이지 않음).
- 본 창(웹·exe)은 CSP 가 없어 연결 서버용 허용을 따로 두지 않는다. WebRTC 는 CSP 로 막히지 않고, `credentialUrl` 요청은 호스트 코드만 연결하는 동안 보낸다. 게임 틀 CSP(`connect-src blob: data:`)·WebRTC 삭제는 그대로 — 틀 안 게임이 연결 서버에 직접 닿을 수 없다.

## 참가 확인 READY · prflx 쌍 받기 (`session.js`·`lan.js`·`net-window.js`, 사용자 2026-11-03 레이드 멀티 참가 실패)

## 인터넷 연결 실패 이유 · 실행 중 설정 바꾸기 (`lan.js`·`session.js`·`signal.js`·`net-host.js`·`net-window.js`·웹 `main.js`, 사용자 2026-11-03 PC·휴대폰 방 코드 참가 실패)

- 증상: 양쪽 "인터넷 연결" 켬, 방 코드 참가가 "○○ 님의 방에 연결하는 중…" 뒤 15초에 실패(유저 기록 "연결 실패(ICE·DTLS)"·"이유 8", 방장 기록 `wanFailed`). 신호(방 찾기·코드 주고받기)는 서버를 거쳐 끝났고, 실패는 기기끼리 바로 잇는 단계다. 15초 = libwebrtc 가 응답 없는 후보 쌍을 버리는 시간 — 상대 공인 주소로 보낸 확인 요청에 한 번도 답이 오지 않았다는 뜻.
- 대칭 NAT 추정(`lan.js` `symmetric`): cone 계열 NAT 뒤에서는 STUN 서버 두 곳이 같은 공인 주소·포트를 돌려주므로 srflx 수 ≤ host 소켓 수, 대칭 NAT(휴대폰 데이터에 흔함)는 서버마다 다른 포트라 srflx 가 더 많다. 내 코드는 `encodeCode` 가 전체 후보로, 상대 코드는 `decodeCode` 가 버리기 전 칸으로 센다(코드 형식은 그대로 — 0.5.2 와 섞여도 된다). STUN 하나가 막히면 덜 세어 추정이 꺼지는 쪽으로만 틀린다.
- 실패 문구(`failCode`·`hintOf`): 양쪽 켬 + 내 망 대칭 = `wanSym`(이 기기를 와이파이에), 상대 망 대칭 = `peerSym`(상대 기기를 와이파이에), 그 밖은 기존 `wanFailed`. 대칭 ↔ full cone 은 붙을 수 있어 "바로 연결되지 않습니다"는 실패가 난 뒤에만 보인다. 기록에는 "공인 주소가 STUN 서버마다 다름(대칭 NAT로 보임)" 과 유저 쪽 "방장 코드 후보 n개(공인 k)" 를 남긴다(상대 기기 기록 없이도 원인을 가리게).
- 실행 중 설정 바꾸기(`NetHost.wanChanged`, exe `applySettings`·웹 설정 스위치가 부름): 세션 값은 만들 때 정해지는데, 창을 닫아도 방이 남는 경우(중간 참가 게임, 웹 시트 바꾸기)에는 다시 열면 같은 방(옛 값)이 보였다. 아무도 들어오지 않은 방장 세션(`idle` = 인원 1, 연결 중·READY 대기 초대 없음)은 바로 바꾸고(`setWan` → `cfg` 증가), `RoomHost` 가 다음 틱에 새 연결 코드로 바꾼다(`stale`·`refresh`, 방 코드 그대로 — 이미 알려 준 코드를 버리지 않게). 코드·QR 화면은 `refreshInvite` 로 초대를 새로 만든다. 누가 들어왔거나 연결 중이면 그 세션은 그대로 두고 다음 방부터 새 값. `snapshot().wan` 은 열린 세션의 값(방 화면 안내 문구가 실제 연결과 맞게).
- `net-window.js` `freshSession`: 연결 전인 참가 시도 세션은 새 참가·방 만들기 때 버린다 — `NetHost.open` 이 열린 세션을 그대로 돌려줘서, 대기 중에 창을 닫고 다시 참가하면 옛 세션(옛 설정)으로 `busy` 오류가 났다.
- 웹 `main.js` `openSheet`: 연결 창은 `#sheetBody` 를 같이 쓴다. 연결 창이 열린 채 상단 버튼으로 다른 시트(설정 등)를 열면 창이 열린 것으로 남아, 멀티플레이 상태가 바뀔 때 새 시트 내용을 연결 창으로 덮어썼다. 시트를 바꿀 때 `netWin.close()`(세션은 그대로, 취소 아님 — 방장 대기 방이 설정을 보는 동안 사라지지 않게). exe 는 설정을 열 때 이전처럼 `requestClose`.

## 중간 참가 게임 (`join: "anytime"`, 사용자 2026-11-02 결정 147, 설계 21절)

- `net-host.js` `setRequest`: `anytime` 게임은 시작부터 요청을 유지하므로(삼국전기) 창을 열지도(`onWant`) 3분 타이머를 걸지도 않고 요청만 둔다 — 열면 시작마다 창이 뜨고 3분 뒤 TIMEOUT 이 왔다. `waiting` = 방장 세션이 열렸고 최소 인원 전(상단 버튼 표시용, 기본 게임도 같은 값이지만 그때는 창이 열려 있음).

## GB·GBC 실행 (사용자 2026-11-02 결정 146, 설계 20절)

### src-bundle/src/js/core/rom-kind.js (새 파일, 웹 빌드 공유 목록)

- `romKind(bytes)`: 머리만 보고 `{ system: "gba" | "gb", color: "" | "only" | "dual" }`. GBA = 3 = 0xEA 이고 (0xB2 = 0x96 또는 0x04~0x9F 모두 0) — mGBA `GBAIsROM` 과 같아 코어(`mCoreIsCompatible`, GBA 먼저)와 같은 쪽을 고른다. GB = 0x104 로고 48바이트의 CRC32(`GB_LOGO_CRC`) — 롬 내용(닌텐도 로고)을 코드에 두지 않으려고 바이트 대신 CRC 만 둔다(`wgbp.js` `findBase` 와 같은 까닭). 둘 다 아니면 지금처럼 GBA.
- `color`: 0x143 비트 7 = GBC 모드(mGBA 자동 판별이 `cgb & 0x80`), 비트 6 까지 서면 전용, 아니면 겸용.
- `systemKind(code, bytes)`: 실행할 때는 코어가 고른 기종(`Web_GetSystem`, 1 GB · 2 GBC)을 믿는다 — mGBA `GBIsROM` 은 로고 앞 4바이트·Sachen 로고도 받아 `romKind` 와 드물게 다를 수 있어서. 색 구분만 머리 0x143 에서.
- `GB_SCREEN`: 160×144·10:9·늘리기 없음. 웹 `setScreen`·exe `state.screen` 이 설명서 `screenOf` 결과와 같은 모양으로 받는다(19절 화면 칸 비율 그대로).
- `kindKey`: 종류 글 키(`rom.gb`·`rom.gbcOnly`·`rom.gbcDual`). 코드가 이름을 고르므로 `i18n-keys.mjs` 의 "표에만 있는 키" 에 나온다.

### src-bundle/src/js/core/web-host.js

- `readScreen`: `Web_Init` 이 성공한 뒤 한 번. 설명서 `screen` 이 있으면(`ownScreen`) 보지 않는다 — 규격의 화면 크기가 우선이고, mGBA 코어(설명서 없음)만 GB 160×144 를 알려 준다. 1024 를 넘는 값은 버린다(버퍼를 읽는 크기라).
- `system`: `Web_GetSystem` 이 없는 wasm(포트·다른 ① 게임)은 0 = GBA.

### src-bundle/src/js/app/player.js

- `GB_LAYOUT`: GBA 10버튼에서 L·R 만 뺀 8버튼(비트 그대로) + `system: "gb"`. `gba` 가 아니어서 터치 L·R 자리가 꺼지고(웹 `touchSlots`) 게임패드 L·R 배치도 없다. `gameId` 가 비어 있어 게임별 키(`gameKeys`)가 아니라 앱 전체 GBA 키를 role 로 이어 받는다(`layoutKeys` → `ROLE_GBA`).

### src-bundle/src/js/pages/index.js (exe)

- `openRom`: 부팅 뒤 `systemKind(host.system, rom)` 로 GB 면 `GB_LAYOUT`·`GB_SCREEN` 을 `startHosted` 에 넘기고 상태 줄에 종류 글. 세이브 id 는 `.gba` 와 같은 `gba/<이름>`(롬 옆 `<이름>.sav`, 상태 `bin/state/<이름>.ssN`).
- `keyLayout`: GB 는 `KEY_ORDER` 에서 L·R 을 뺀 순서·기본 키·안내(`cfg.keys.gb`). 라벨은 비워 두어 설정 창이 `key.*` 를 쓴다.
- `applySettings`: GB 게임 중 저장하면 설정 창이 8개 키만 돌려주므로 앱 전체 키(`keysFromPrefs`)에 덮어 합친다 — 그대로 쓰면 L·R·C·D 키가 지워진다.
- `helpBody`: GB 는 GBA 순서에서 L·R 만 뺀 줄.

### web/src/js/main.js (웹)

- `storedType`: 보관 종류를 확장자가 아니라 머리로(`gb`·`gbc` + `color`). `.wgba`·`.wasm` 은 그대로. `webRomFor` 의 후보는 `type === "gba"` 라 GB 롬은 웹 빌드 롬 후보에 나오지 않는다.

- `startHosted(…, kind)`: GB 면 설명서 화면보다 먼저 `GB_SCREEN`. `state.game.kind` 는 시험이 본다.
- `kindText`·`metaKind`: 종류 글 "GB"·"GBC 전용"·"GB·GBC 겸용"(라이브러리 칸·첫 화면 최근 줄). 옛 보관 항목(`gba`)은 그대로 `.gba`.
- `unzip`: 열기에서 롬이 없는 ZIP 은 `web.zipNoGame`(.gba·.gb·.gbc). 패치 바탕 롬 ZIP(`patch.err.zipNoRom`)은 GBA 만이라 글을 나눴다.
- `renderHelp`: GB 는 GBA 순서에서 L·R 만 뺀 줄(설명서 게임 줄 모양이 아니라).
- `packNode`: GB 롬팩은 `data-shape="gb"` — 몸통이 좁아 실행 중 칩을 몸통 오른쪽 위로(`web.css` `.pack[data-shape="gb"] .pack__chip`, 몸통 끝 46열 → 오른쪽 8칸 × 2px − 4px = 12px). 그림 없는 롬팩이라 배율은 늘 2.

### web/src/js/cart.js

- `cartModel` → `shape`: 설명서 없는 `gb`·`gbc` 보관 항목만 `"gb"`(설명서 게임은 그림·색 규칙 그대로). 색: `gb` = `GB_BODY`(회색), `gbc` = 이름 해시 색(결정 102-8).
- `gbFront`: 같은 54×44 격자 안에 세로 몸통(`GB_X` 8~45열, 좌우 투명 — 책장·첫 화면 자리 계산을 바꾸지 않으려고 격자 크기는 그대로). 라벨 종이 `GB_PAPER`, 이름 글 자리 `GB_TEXT`(위 띠 2줄 아래 ~ 아래 그늘 줄 위). 실제 카트리지·상표 모양을 따르지 않는다(기본 GBA 모양과 같은 원칙).
- `defaultSpine(…, shape)`: GB 는 위 홈 1줄(2행 어두운 줄 + 3행 밝은 줄)·아래 줄 1줄, GBA 는 지금처럼 아래 두 줄.

### web/src/js/store.js · src-bundle/src/js/core/zip.js

- `putRom`: `color` 가 있을 때만 기록(GBA 항목 모양은 그대로).
- `zip.js` `GAME_NAME`: 일반 열기(`extractRom`)만 `.gb`·`.gbc` 를 받는다. 패치 바탕 롬(`romChoices`·`zipRoms` 기본값 `ROM_NAME`)은 GBA 만.

### web/tools/check-no-rom.mjs

## zip 안 여러 게임 고르기 (사용자 2026-11-03, 설계 23절)

### src-bundle/src/js/core/zip.js

- `zipGames`: 게임 파일 전부(`.wgba`·`.wasm`·`.gba`·`.agb`·`.gb`·`.gbc`·`.bin`, 폴더 안 포함, `__MACOSX`·`._*` 제외)를 표시 이름 → 경로 순(숫자 자연 순서)으로. 줄마다 `problem`(암호·풀 수 없는 방식·크기 초과) — 팝업이 체크 불가 줄로 보인다. 크기 한도: 롬 `MAX_ROM`(exe 는 `romMax` 64MB = `read_rom`), `.wgba`·`.wasm` 은 `ZIP_MAX`.
- `zipReadAsync`: 압축 바이트를 256KB 씩 `Inflate` 에 넣고 12ms 마다 양보(`setTimeout 0`) — 50개·30MB 항목에서도 화면이 멈추지 않게. CRC 는 나온 조각마다 `crc32Step` 으로 이어 계산(다 푼 뒤 한 번 더 훑지 않음). `signal.aborted` 면 `zipCancelled`.
- `zipName`: exe 가 Rust 에서 받은 원래 이름 바이트를 웹과 같은 규칙(UTF-8 → EUC-KR)으로 읽게 내보냄.

### src-bundle/src/js/app/zip-pick.js (웹·exe 공용)

- `zipPicker`: 줄 전체가 `role="checkbox"`(탭·클릭 칸이 넓게), 체크 그림은 `aria-hidden` 칸. Space 는 누르는 동안 `is-down`(눌림 모양) → 뗄 때 바뀜(기본 체크박스와 같은 순서), Enter 는 바로 바뀜, ↑↓ 는 다음 쓸 수 있는 줄로. 호버 모양 없음(터치 뒤 남지 않게), 포커스 모양은 `:focus-visible` 만.
- 같은 이름 줄만 폴더 이름 하나를 형식·크기 앞에(설계 "화면에는 파일 이름만"). 등록 이름도 `이름 (폴더).확장자` — 같은 이름 = 같은 항목인 라이브러리에서 서로 덮지 않게.
- 글자 잉크 가운데는 `board-panel` 의 `centerBoardNodes` 를 쓰되, 말줄임된 이름은 보이는 글자 + "…" 로 잰다(`shownText`) — 숨은 `g`·`y` 아랫부분까지 재면 2px 위로 뜸.
- `openCountLoader`: 150ms 뒤에야 보인다(빨리 끝나는 zip 에 깜빡임 없게), 보일 때 `onShow`(웹: 알림 닫기). 웹 `.loader--count` 는 확인 창(z 30) 아래(z 29) — 등록 중 낮은 버전 경고가 로더 위에 뜨게.

### web/src/js/main.js

- `openZip`: zip 은 다른 형식과 달리 읽고 고르기 전에는 지금 게임을 닫지 않는다(취소하면 그대로 이어서). 읽는 동안 `hold("zip")` 로 게임 멈춤. `File.stream()` 으로 읽어 읽은 크기를 로더에(없으면 `arrayBuffer`). ZIP 은 `ZIP_MAX` 까지.
- 게임 1개면 풀어서 지금처럼 `openBytes`(= 예전 `openFile` 뒷부분, `.wgba` 는 버전 비교 그대로) → 실행. zip 안 `.wgba` 1개도 이 길로 열린다.
- `addZipGames`: 고른 게임마다 `importGame`(단일 파일 추가와 같은 흐름 — `.wgba` 높은 버전 = 업데이트, 낮은 버전 = 경고, 같은 빌드 = 그대로). 실행하지 않고, 끝나면 라이브러리 시트를 연다. 취소는 지금 게임을 마친 뒤 멈추고, 이미 등록한 것은 남긴다.
- 팝업이 열릴 때·로더가 보일 때 알림(`toast("")`)을 닫는다 — "여는 중" 알림이 팝업 아래에 남지 않게(총괄 지적).
- `openDialog` 가 글 대신 노드도 받고(`kind` → `#dialog[data-kind]`), 고르기 팝업만 본문을 세로 flex 로(목록만 스크롤).
- 정보 화면 문서 링크(`/LICENSE.txt` 등 같은 출처 `.txt`): 설치형 PWA(특히 iOS)는 범위 안 주소를 `target="_blank"` 라도 앱 창 안에서 열어 돌아올 길이 없었다 → 링크를 눌러도 이동하지 않고 앱 안 문서 시트(`openDoc`·`renderDoc`)로 보인다. "정보" 버튼 = 정보 화면, 닫기·뒤로 가기 = 시트 닫힘(게임 계속). GitHub·블로그(범위 밖)는 새 탭(`outLink`, `noopener`). `.txt` 는 오프라인 캐시에 없어 오프라인이면 불러오지 못했다는 글.
- 블로그 줄(사용자 문구 "블로그: https://flightrabbit.tistory.com"): 저작권 줄 바로 아래 `.note.info__line`. 라벨을 `span` 에 두어 `textInk` 가 줄 전체 글자(라벨 + 주소)로 잉크를 잰다.
